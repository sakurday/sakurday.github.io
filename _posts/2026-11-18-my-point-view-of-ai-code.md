最近，我在刷抖音时看见一些“古法编程”的视频，评论区清一色的都是嘲讽，“现在都是 AI 时代了，还在古法编程”，“这就像学了钻木取火，结果找工作的时候发现大家都用打火机”。

每当看到类似于这种评论，我心里都有一股无名火。古法编程是基础，至少你得了解很多计算机相关的知识。理论多说无益，我举个例子：

---

一个没学过编程的人，我暂且称之为“小明”

小明：帮我做一个聊天软件

豆包：我将用 Python 实现一个简单的聊天软件，可以在 Windows 上运行：[此处省略一万行代码] 软件做好了，你可以下载它，然后保存到一个空白文件夹，在终端输入 python msg.py 来运行聊天软件。

小明：这个啥终端是什么，你为什么搞这么复杂，我想和 QQ 一样点一下就能打开

豆包：我太懂你现在的感受了！其实你可以直接双击打开它，不需要终端

小明：这个怎么回事，为什么我打不开？

豆包：你的系统没有安装 Python ，如果你是 Windows ，请你前往 Python 的官方网站下载[此处省略一万字]

小明：Python 是什么？为什么这个网站这么慢啊

豆包：[此处省略一万字]

经过了一百轮对话后

小明：终于能打开了！但是你这个聊天软件里咋还要啥 IP 地址啊？这个开放公网是什么东西？界面怎么这么丑？为什么不能发红包？好友怎么加进来？

豆包：简单来说，IP 就是你设备的地址簿......

小明：啥玩意我听不懂！我要你做一个双击就能打开的聊天软件！要像 QQ 一样！复制号码就可以加好友！你这弄的什么玩意这么复杂！......

豆包：我太懂你这种感受了，聊天软件不能运行，换作是谁都很沮丧。我为我的行为道歉，我会稳稳的接住你......

---

再来看另外一个例子：

---

一个对计算机知识略懂一二的初级古法程序员，我们暂且称之为“小红”

小红提前在电脑上安装了 Python 环境和一些依赖库

小红：请为我实现一个聊天软件，要求如下：使用 Python 分别实现客户端和服务端，客户端使用 Tkinter 作为 UI，服务端使用纯命令行实现。支持 Windows 系统。服务端作为聊天服务器，使用 MySQL 作为存储用户信息的数据库，客户端通过 IP 地址连接服务端。支持好友添加，文字和图片聊天，语音聊天和通话。支持添加表情，支持扫码添加好友，聊天消息使用端到端加密。客户端通过 SQLite 存储历史聊天记录等信息。客户端所有储存文件存放在程序本身所在文件夹下。做好用户注册，用户可以通过手机号注册，使用阿里的短信接口发送短信（接口文档已放在xxx）并做好验证码校验。登录使用密码+手机号，同时做好找回密码。最终交付时将客户端和服务端放到不同文件夹下，客户端编写一个打包脚本，运行脚本时使用 Pyinstaller 将客户端打包成单文件 exe ，包含所有依赖项目......[此处省略一万字]

肥鱼：[省略十亿 Token 的雷霆长思考] 最终程序已按要求交付在 xxx 文件夹下......

小红熟练的在终端启动服务端，然后运行了客户端，通过 127.0.0.1 成功连接服务器。他在路由器开放了他电脑的 xx 端口，然后把程序和 IP 发给好友，好友立马就连上了服务器，然后行云流水般添加了好友，畅快的聊天......

---

在 AI 彻底重构计算机和操作系统架构之前，学会一点古法编程（或者一点点计算机基础知识）是非常必要的。AI 只是让一个古法编程的人可以干三个古法编程人的活，并不能让一个没接触过任何编程的人写出好用的软件。抖音上那些嘲讽古法编程的人，试问一下，你们有谁真正拿 AI 做出过可长期使用的软件了？

那就有人要问了，说了这么多，我做出来啥名堂没有啊？

还真有，如果你关注过我的 GitHub，可以发现我还是做出来了一些有用的东西的，而且我每天都在用，并不是过把瘾后就放着吃灰：

- MultiYggdrasil 一款 Minecraft Java 版模组，游戏内切换不同第三方登录账号。类似模组仅能切换正版与离线账号，不支持第三方。

- CSync 以极低的个位数 M 占用和简洁的界面提供手机与电脑的无感剪贴板同步。类似软件要么占用不小，要么受制于 Android 的限制。
